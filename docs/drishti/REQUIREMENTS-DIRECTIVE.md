## Product and environment
One application for: (1) authorised live CCTV viewing, recorded playback and video exports across CityKart locations; (2) central monitoring of CCTV cameras, NVRs, servers, desktops, laptops, attendance machines, footfall machines and other network-connected IT assets; (3) controlled IT remote support and endpoint administration; (4) proactive detection, investigation and resolution of operational IT problems.

Locations connect through SD-WAN. Head office can reach location assets over the company network. TightVNC is installed on many endpoints, RDP on some. Windows endpoints include workgroup and domain-joined machines. docs/ARCHITECTURE-AND-DESIGN-FOR-REVIEW.md is the starting point; its "BUILT" markers are claims to verify against code and tests.

## Access control — required corrections
Separate organisational roles, resource scopes and permitted actions.

CCTV actions independently assignable: live viewing; recording search and playback; video download/export.
IT actions separately: asset inventory and monitoring; remote screen viewing; remote screen control; diagnostic collection; script execution; software installation/uninstallation; configuration deployment; patch management; credential administration; OS deployment.

A CCTV store grant must not automatically grant access to servers or IT management. Assignment cases: all cameras in one store; all cameras across selected stores; selected cameras in one store; selected cameras across multiple stores; different live/playback/export rights for the same coverage.

Remove hidden grant behaviour (adding one camera silently narrowing an existing whole-store grant). Define explicit assignment modes and predictable overlapping-grant rules. Do not grant CCTV access solely because a profile names a home store. A generic manager role must not be globally privileged; assign its coverage explicitly. Provide an effective-access preview before an administrator saves assignments. Enforce permissions on every relevant server operation: recording searches, thumbnails, stream creation, clip jobs, file downloads. Camera groups must never expand access; filter membership responses and displayed metadata. Include grant expiry, deactivation and prompt revocation of active sessions; set and test a revocation target of ≤ 60 seconds for active video and remote sessions. Rename the human "agent" role to "operator".

## Asset and location model
Stores, head office, DCs and other locations. A location may contain multiple NVRs — do not keep one recorder's address/credentials as the only NVR model on the store record. Model locations, NVRs, cameras and recorder/channel mappings explicitly; preserve stable camera identities and grant history when mappings change. Support parent dependencies (location → SD-WAN → switch → NVR/endpoint). Stable asset identities with serial/MAC/model/firmware, ownership, criticality, lifecycle, warranty, last inventory refresh. IP address is an attribute, not the sole identity; determine how SD-WAN addressing handles overlapping networks before enforcing global IP uniqueness. Migrate existing data without silently losing grants, camera identities or monitoring history.

## CCTV implementation
Complete live viewing, camera groups, playback and authorised clip exports: substreams for grids, main streams on demand; recording calendar/timeline with clear unavailable intervals; correct IST display and explicit NVR clock offsets; test recordings crossing midnight; bound live/playback/export concurrency; stop hidden/abandoned streams; audit viewing sessions, searches, exports without logging credentials or bearer tokens; expiring authorised downloads; export retention, cleanup, storage quotas; distinguish user clip exports from scheduled evidence backup. Test actual codec/browser combinations (RTSP conversion alone does not prove a browser can decode). Show reachability, stream availability and recording health separately.

## Monitoring and control centre
Compact operational overview: locations affected; network/location outages; CCTV recording failures; unavailable/degraded cameras; critical server/endpoint problems; monitoring coverage and stale data; incidents awaiting action; recent recovery and change events. Every summary opens a useful investigation (affected assets, observations, timeline, root-cause evidence, authorised next actions); preserve filters on return. Distinguish: confirmed device/service failure; unreachable from head office; unknown because a parent/location is unreachable; stale monitoring; maintenance; healthy observation. Do not label all cameras physically failed because their NVR or WAN is unreachable. Correlate parent incidents, suppress duplicate notifications, retain child observations. Report observed availability, unknown time and monitoring coverage separately; excluded monitoring gaps must not appear as proven healthy time.

Capability-based checks: NVR storage/recording errors, recording gaps, retention, clock drift; camera stream decode and stale/frozen/black frames where supported; SD-WAN latency, loss, tunnels, failover where accessible; switch/AP/PoE and UPS/printer health where supported; Windows performance, disk trends, required services, security status, patch age, pending reboot; attendance and footfall data freshness through available integrations. Unsupported checks show unavailable/unsupported, never fabricated healthy values.

Alert routing: configured channels, deduplication, maintenance suppression, acknowledgement, escalation, recovery messages; configurable WhatsApp/webhook integration if supported by existing infrastructure; send no external messages during development.

## Endpoint agent and remote management
Outbound agent is the primary endpoint mechanism for mixed workgroup/domain machines; retain controlled WinRM, SSH, SNMP and vendor-API adapters where useful. Start with read-only inventory and health collection (computer name, serial, hardware; Windows edition/version/build, join status; installed applications and versions; CPU, RAM, disks, uptime, services; security/update status, pending reboot). Define secure enrolment, device authentication, rotation, revocation, upgrades, local credential protection.

**Correct the signing contradiction**: a server storing only a token hash cannot sign commands with the original token. Use a separate command-signing authority with public-key verification at endpoints. Bind each signed command to device, job, immutable script/package version, exact parameters, expiry and policy version. A compromised device credential must not authorise command creation or approval.

Execution: versioned approved script/package library; no unrestricted fleet-wide command box; persistent local execution journal; leases, acknowledgements, reconciliation; do not blindly rerun a job because an acknowledgement timed out; revalidate queued commands when an offline PC returns; supersede obsolete configuration jobs; action-specific expiry and maintenance windows; approval bound to the exact immutable payload; canaries, bounded batches, pause/cancel, failure-stop thresholds; rollback/recovery per action. Implement software install/uninstall, wallpaper, screensaver, approved batch/PowerShell execution and patch management in controlled stages. Handle per-user settings correctly when the agent runs as SYSTEM. Verify results rather than assuming an exit code proves the requested state. Use Windows LAPS for eligible joined devices; design workgroup password management separately. Do not enable local administrator accounts as a default fleet action. Remote screen view and control permissions are separate; enforce view-only in the protocol path, not only the UI. Rotate shared VNC credentials through a controlled migration. Do not claim downloaded RDP files provide Drishti-enforced session controls.
