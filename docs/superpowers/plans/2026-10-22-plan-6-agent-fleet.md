# Device Agent, Health and Fleet Commands (Plan 6 of 7) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A small Windows agent on every desktop, laptop and server reports health (CPU, RAM, disks, errors, updates), hardware and software inventory (serial numbers, Windows version, installed programs), and carries out IT commands from the hub: run approved PowerShell scripts (wallpaper, screensaver, cleanup, configuration), install software, rotate local administrator passwords, enable the built-in administrator account, restart, and run Windows Updates. Commands for a PC that is off or offline wait in a queue and run, in order, the next time it comes online.

**Architecture:** The agent (PowerShell 5.1, already on every Windows 10 and 11 PC, no domain needed) makes outgoing HTTPS or HTTP calls over the VPN to the hub: one check-in a minute that sends metrics and receives due commands. Commands are rows (`agent_jobs`) with a state machine and an expiry; the hub hands out only due commands, signs each with the device's own secret, and the agent verifies the signature and an allow-list before running anything. Fleet commands expand one request into one job per PC after a second administrator approves it. Health rules run in the database when data arrives and open or close problems, each with a suggested fix script.

**Tech Stack:** Next.js 16 route handlers for the agent API, Supabase (Vault for local administrator passwords), PowerShell 5.1 for the agent, `exceljs` (from Plan 4) for exports, the worker for retention and queue maintenance.

**Spec:** `docs/superpowers/specs/2026-10-21-network-monitoring-hub-design.md` plus the chat decisions of 2026-10-22 (Windows 10/11 only, mixed domain and workgroup, more than 1,000 systems on the VPN, no Intune or SCCM; needs: serial numbers and Windows versions, change all administrator passwords at once, enable the administrator account, install software on all machines at once, queue commands for offline PCs, run PowerShell scripts for wallpaper, screensaver, cleanup, errors, performance and configuration).

## Global Constraints

- All earlier constraints apply (Next 16, Server Actions check the caller first, services return `Result`, explicit grants on every new object and function, egress guard and loopback fakes in tests, plain English, IST 24-hour times, no secrets in the repo, never push).
- **No test or demo ever changes a real machine.** Tests run the agent only in `-DryRun`/`-SelfTest` modes; the only script the agent executes on the development PC during the demo is `collect_info`. No test reboots, changes accounts, installs software or writes registry keys outside a temp location. Reboot, account, install and registry jobs are exercised only through the hub's queue logic and against a fake executor.
- Agent API authentication: each agent has its own random device token (32 bytes, shown once at enrolment, stored only as a SHA-256 hash). Enrolment uses a one-time or limited-use enrolment token created by an administrator (stored hashed, with expiry and use limit). Every agent call is rate limited (check-in at most once per 20 seconds per device; enrolment 10 per minute per address hash). Agent routes are exact public paths in `proxy.ts` and authenticate themselves.
- Commands: only these kinds exist (allow-list in the database): `collect_info`, `run_script`, `install_package`, `reboot`, `set_admin_password`, `enable_admin_account`, `windows_update_scan`, `windows_update_install`, `run_diagnostic` (read-only: printers, local network and mapped drives). Scripts come only from the script library (created by administrators, versioned); there is no free-text "run this on 1,000 PCs" box without approval.
- Approval: a fleet command that changes anything and targets more than one PC, or any command of risk `high` (reboot, account changes, install, any script marked high), needs approval by a second administrator (never the requester). Low-risk single-PC commands by an administrator run at once, and read-only commands (`collect_info`, `run_diagnostic`) never need approval.
- Every command carries an expiry (default 30 days) and `not_before`. States: `awaiting_approval`, `queued`, `sent`, `running`, `succeeded`, `failed`, `expired`, `cancelled`, `rejected`. A `sent` command with no result after 15 minutes returns to `queued` (up to 3 attempts, then `failed`). Per PC, commands run one at a time in order of priority then creation time.
- Each command is signed at hand-out time with HMAC-SHA256 over `jobId|kind|canonical params|expires` using the device token; the agent refuses a command with a bad signature, an expired one, or a kind not enabled in its local configuration.
- Local administrator passwords are generated **on the PC** (20 random characters), returned once in the command result, immediately moved to the vault by the hub (`device_admin:<deviceId>`) and removed from the stored result; they are revealed only to administrators through an action that asks for a reason and writes a `security` system-log entry. They are never logged, exported or shown in lists. Production must use HTTPS between agents and hub (the runbook says so; the dev demo uses HTTP on loopback).
- Software packages: winget IDs (the PC must reach the winget source) or files hosted by the hub with a SHA-256 the agent verifies before running; silent arguments are fixed per package by an administrator.
- Health data: raw metrics kept 30 days, hourly rollups 400 days, events 90 days, software and hardware replaced on each daily inventory.
- Windows 10 reached end of support on 14 October 2025: the fleet dashboard marks Windows 10 PCs "Windows 10 (security updates ended)".
- `npm run typecheck`, `npm run lint`, `npm run test:unit`, `npm run test:integration` clean at the end of every task. PowerShell tests run only on Windows (`it.skipIf(process.platform !== 'win32')`).

### Task 3: Ingest and health rules (database function)

**Files:** Create `supabase/migrations/20261021000013_agent_data.sql` additions or a new `…013b_agent_ingest.sql` (your choice) with `agent_ingest`; `lib/agent/ingest.ts`; tests `tests/integration/agent-ingest.test.ts`.

`agent_ingest(p_device uuid, p_org uuid, p_payload jsonb) returns jsonb` (service role only): payload keys all optional: `metrics {at, cpuPct, ramPct, ramUsedMb, disks [{drive, totalGb, freeGb}], uptimeS, pendingReboot, pendingUpdates, lastUpdateAt, avStatus, smartStatus}`, `hardware {...}` (upserts `device_hardware`), `software [{name, version, publisher, installDate}]` (replaces the device's set), `events [{at, log, eventId, level, provider, message}]` (insert, ignore duplicates, message cut to 500), `serverTime` is returned. After storing metrics it evaluates health rules and opens or closes `device_problems` (one open per kind; closing when the condition clears) and returns `{ opened: [...], closed: [...] }`:
`disk_low` (any fixed drive free < 10% → warning, < 5% → critical; suggested script `cleanup_temp`), `ram_high` (average RAM over the last 10 samples > 90%; script `restart_spooler`? no: suggested `collect_info`, none better), `cpu_high` (average CPU over the last 15 samples > 95%), `smart_unhealthy` (`smartStatus` not 'Healthy' and not null → critical), `updates_stale` (`lastUpdateAt` older than 45 days → warning; script `windows_update_scan`), `pending_reboot_long` (pending reboot true and the oldest consecutive pending sample older than 7 days → warning; suggested `reboot`), `av_off` (`avStatus` = 'Off' → critical), `many_errors` (more than 20 error events in the last hour → warning), `uptime_long` (uptime over 60 days → warning), `time_skew` (agent time differs from server time by more than 5 minutes: payload `agentTime`; warning). Thresholds are constants in one SQL block so they can be changed in one place later.

The device is found by an existing agent with the same hostname+serial in the same organisation (re-enrolment replaces the token) or created (type from `deviceType`, default `desktop`; name = hostname; `ip` = reported address or `0.0.0.0`... use the reported ip if it is a valid IP, else `127.0.0.2` is **not** allowed: reject enrolment without a valid IP with the plain message "The computer did not report its address."; store from the token's `store_id` or the `storeCode` if it exists in the organisation; the unique `(org_id, ip, tcp_port)` rule means two PCs cannot share an address: report a clear conflict message). ### Task 7: The PowerShell agent

**Files:** Create `agent/windows/CityKartAgent.ps1`, `agent/windows/Install-CityKartAgent.ps1`, `agent/windows/Uninstall-CityKartAgent.ps1`, `agent/windows/README.md`; tests `tests/unit/agent-ps.test.ts` (Windows only).

Requirements (PowerShell 5.1, no external modules, ASCII only):
- **Config** `C:\ProgramData\CityKartAgent\config.json`: `hubUrl`, `enrollToken` (removed after enrolment), `deviceToken` (stored after enrolment, ACL restricted to SYSTEM and Administrators), `storeCode`, `intervalSec` (60), `allowJobs` (true), `allowedKinds` (default all eight), `deviceType`. Log file `agent.log` in the same folder, rotated at 2 MB (keep 3). Never log tokens, passwords or job output beyond 200 characters.
- **Modes:** `-Once` (collect and print or send one cycle), `-DryRun` (collect and write JSON to `-OutFile`, never contacts the hub, never runs jobs), `-SelfTest` (runs a built-in battery without touching the system: JSON shape, signature verification, allow-list refusal and a fake job through the executor with a stub that only echoes), default (service loop).
- **Collection:** hostname; primary IPv4 (the one used for the default route) and MAC addresses; manufacturer, model, **serial number** (`Win32_BIOS.SerialNumber`, fall back to `Win32_ComputerSystemProduct.IdentifyingNumber`; treat common placeholder values such as "To be filled by O.E.M." as empty), BIOS version, CPU name/cores, RAM total, disks (model, serial, size, health via `Get-PhysicalDisk` when available), GPU; **Windows** caption, version, build, edition, install date, activation status (`SoftwareLicensingProduct` with a non-null `PartialProductKey` and `ApplicationId = 55c92734-d682-4d71-983e-d6ec3f16059f`), domain joined and domain or workgroup name, last boot; metrics every cycle (CPU load average, RAM percent, fixed drives free and total, uptime, pending reboot from the three registry indicators, Defender state via `Get-MpComputerStatus` when present else `Off`/`Unknown`, SMART summary); daily (and at start): software list (from the two Uninstall registry hives, name/version/publisher/installdate), pending Windows updates count and last installed update date (via `Microsoft.Update.Session`, wrapped in a 90-second timeout job); events each cycle: System and Application errors and critical events since the last cycle (max 20, message cut to 300 characters).
- **Enrolment:** if no `deviceToken`, POST the enrolment (token, hostname, serial, MACs, IP, store code, OS, version) and store the returned token; on 401 delete the stored token and enrol again only if an `enrollToken` is present.
- **Check-in:** POST `/api/agent/checkin` with the collected data and the results of finished jobs; receive jobs; for each in order: verify the signature (`HMACSHA256` with key = SHA-256 hex of the device token over `jobId|kind|canonical params|expiresAt|scriptSha256`), refuse expired or not allowed kinds (report `failed` with a plain reason), then execute (below), save the result in `state.json` before sending so a result survives a reboot or crash, and send it on the next check-in.
- **Executors** (each has a `-WhatIf`-style dry mode used by self-test and returns `{status, exitCode, output}`): `collect_info` (force a full inventory); `run_script` (writes the signed script body to a temp file, runs `powershell.exe -NoProfile -ExecutionPolicy Bypass -File` with the given arguments and a timeout of 15 minutes, captures stdout and stderr, deletes the file); `install_package` (winget: `winget install --id <id> --silent --accept-package-agreements --accept-source-agreements --disable-interactivity`; file: download from the hub with the bearer to a temp folder, verify SHA-256, run with the silent arguments, delete the file; both with a 60-minute timeout); `reboot` (`shutdown.exe /r /t <delay> /c "Restart requested by IT"`; the job is reported `succeeded` before the shutdown starts); `set_admin_password` (find the built-in administrator by SID ending `-500` unless a name is given, generate 20 random characters with `System.Security.Cryptography.RandomNumberGenerator` including upper, lower, digit and symbol, set it with `Set-LocalUser`, return it in the result field `secret`); `enable_admin_account` (`Enable-LocalUser` on the SID `-500` or given account; report whether it was already enabled); `windows_update_scan` / `windows_update_install` (COM API: search, optionally download and install, report counts and reboot required; install only when `rebootIfNeeded` is allowed to restart).
- **Installer** `Install-CityKartAgent.ps1 -HubUrl <url> -EnrollToken <token> [-StoreCode X]`: must run as administrator; copies the agent to `C:\ProgramData\CityKartAgent`, writes the config, registers a scheduled task `CityKartAgent` (at startup, run as SYSTEM, highest privileges, restart on failure every minute up to 999 times, no time limit) that runs the agent loop, starts it, and prints what it did; `Uninstall-CityKartAgent.ps1` removes the task, the folder and nothing else.
